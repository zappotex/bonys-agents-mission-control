# Mission Control 0.2.7

## Behoben: Schreiben aus dem Browser in der Docker-Installation

- In der Installation auf einem Agent-PC (Docker) lehnte Mission Control seit 0.2.0 jede schreibende Anfrage aus
  dem Browser mit `403 forbidden` ab – Missionen anlegen und starten, Chat und Profile speichern gingen nicht.
  Grund: Im Container kommt die Anfrage nicht von `127.0.0.1`, sondern vom Gateway des Container-Netzes.
- Mit `MISSION_CONTROL_LOCAL_ONLY=true` (Standard in `compose.yaml`, Port nur an 127.0.0.1 freigegeben) gilt im
  Container jetzt zusätzlich das Standard-Gateway als lokal. Origin und Host müssen weiterhin Loopback sein und
  übereinstimmen; andere Container-Adressen bleiben ohne Token draußen. Dabei wird auch ein geänderter
  `MISSION_CONTROL_PORT` richtig behandelt.

## Behoben: Modell und Auftragstext bei Hermes-Aufträgen

- Chat und Missionen schickten fest `model: "hermes-agent"` an `POST /v1/runs`. Hermes übernimmt bei Runs das
  Modell immer – mit einem echten Anbieter wie OpenRouter scheiterte jeder Auftrag („not a valid model ID“).
  Jetzt geht kein Modell mehr mit; jeder Agent nimmt das in seinem Hermes-Profil eingestellte Modell.
- Titel und Beschreibung einer Mission kamen mit einem wörtlichen `\n\n` statt einer Leerzeile bei Hermes an.
